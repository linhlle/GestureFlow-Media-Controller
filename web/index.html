Hand tracking · macOS · open source

Wave at your Mac and it does things.

GestureFlow watches one hand through your webcam and turns it into the cursor, clicks, scrolling, volume and keyboard shortcuts. I built it to find out whether gesture control could be made reliable enough to actually live with — or whether it was always going to stay a demo.

Try it on your hand → Install the desktop app

A web page cannot touch your Mac. It can't move your cursor, press your shortcuts or change your volume. No site can — browsers don't hand out that kind of access, and I'd rather say so plainly than let the demo imply otherwise.

So the demo here shows you the recognizer thinking, on your own hand, in real time. It names the mode it would be in. Actually doing anything to your machine is the desktop app's job.

01 Same forest, same state machines, two runtimes.

What runs where

The browser gets the recognizer. The Mac gets the recognizer plus the ability to act on it.

In your browser no install

  • Live hand tracking from your webcam
  • The actual trained forest, exported to JSON — not a reimplementation that drifts the first time I retrain
  • The same click, scroll and debounce state machines, ported to JS and held to it by a parity test suite
  • A command builder that writes you a config file
  • Video never leaves your machine. There is no server to send it to; the site is static files

On your Mac python app

  • Moves the real cursor and sends real clicks
  • Fires keyboard shortcuts and launches apps
  • Drives system volume through AppleScript
  • Loads the config you built on this site
  • Needs macOS Accessibility permission, which only you can grant — there's no way around that, and it's the right call
02 Four stages, each on its own thread.

How it works

Most of the difficulty isn't recognising a pose. It's deciding whether you meant it.

StageWhat happens
Capture Grabs a camera frame and runs MediaPipe Hands for 21 3D landmarks. Reconnects with backoff when the camera vanishes, because sooner or later it does.
Inference Turns landmarks into 63 features — wrist-relative, then divided by the largest component, so the vector reads the same wherever your hand sits in frame and however far away it is. A 100-tree random forest classifies the pose.
Stabilisation A majority vote over ten frames, then state machines with hysteresis. This is the part that separates a gesture from a hand that merely passed through the shape on its way to a coffee cup. Clicks fire on release, not on contact.
Action A dedicated thread makes the OS call, so a slow shortcut can't stall the video. Cursor moves collapse to the newest position; a stale one just walks your pointer somewhere you no longer want it. Clicks are never dropped.
03 Config is data. There is no eval anywhere in it.

Your own commands

Bindings live in a file you own, not in my source code.

Pick a gesture, choose an action, download the file, drop it in ~/.gestureflow/. The app checks it on load and picks up your edits without a restart — and if you save something broken it keeps running the last good config rather than falling over.

Nine action types: keyboard shortcut, single keypress, media key, launch an app, open a URL, type text, a chord, AppleScript, or a command. A config can arrive by download, so it's treated as untrusted input: key names are checked against a whitelist, and shell takes an argument list and runs without a shell, so pipes and && are literal text rather than syntax. 

version: 1
neutral_label: 0

gestures:
  - label: 1
    name: Spotlight
    action:
      type: hotkey
      keys: [command, space]

Why there are no numbers on this page

You won't find a frame rate, a latency figure, an accuracy percentage or a false-trigger rate anywhere on this site. Not because they'd be unflattering — because they'd be meaningless. All of them depend on the camera, the CPU and the lighting in front of them, so a number I measured on my laptop tells you nothing dependable about yours.

What ships instead is the instrumentation to measure it on your own hardware. gestureflow bench reports per-stage timings and end-to-end latency as p50/p95/p99. gestureflow false-triggers replays footage you recorded while deliberately not gesturing, and counts everything that fired anyway. The guide walks through both.

The one number you will see is in the demo, in the corner of the video, measured live in your own tab as it runs.
