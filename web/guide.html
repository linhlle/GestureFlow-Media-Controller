GestureFlow Live demo Command builder Guide

Gesture vocabulary

Two families. Poses are classified by the trained model; everything else is geometry measured directly from the landmarks.

Trained poses

These go through the Random Forest and a 10-frame majority vote. What each one does is up to your config — the defaults are below.

LabelPoseDefault action
0Neutral Nothing — this is what enables all the modes below
1L-Shape Spotlight (⌘Space)
2High-Five Mission Control (⌃↑)
32-Finger App Switcher (⌘Tab)

Safety: the pause switch

Index and pinky up, middle and ring curled — "rock horns" — held for about a second and a half toggles all control off. Hold it again to resume. While paused the app keeps tracking and the window says PAUSED in large letters, but nothing reaches your Mac.

It is deliberately a pose you will not strike by accident: it needs four finger conditions at once, held continuously, and a single frame that breaks the pose resets the timer. It also avoids the thumb entirely, because thumb geometry is the least reliable part of hand tracking and a kill switch should not be built on it.

Geometric modes

Active only while the classifier reads Neutral. At most one runs at a time, decided by a single precedence ladder rather than by each mode trying to exclude the others — so two can never fire at once.

Every threshold below is a fraction of your hand's size (wrist to middle knuckle), not an absolute distance, so the gestures behave the same whether you are close to the camera or leaning back. If they still feel off, calibration fits them to your hand.

ModeHow to trigger itGate
Cursor Point your index finger up Index tip clearly above its middle joint
Left click Touch thumb to index tip, hold, then release Fingertips within 0.28 of your hand's width, held 4 frames; fires on release past 0.41
Right click Touch middle finger to index tip, hold, release Same, but 5 frames and a 0.6 s cooldown
Scroll Make a fist, then move your hand up or down All four fingertips curled below their knuckles, thumb not raised, held 5 frames, moving mostly vertically
Volume Thumb up, index down; move up or down Thumb straight and clear of the index knuckle, index not extended
Drag Pinch, keep holding, move, then release The pinch held past the click threshold for another ~0.55 s
Swipe Closed fist, flick left or right Same fist as scroll, but horizontal motion winning by half again
Zoom Index up and thumb out sideways; spread or close them Thumb at 65°+ to the index, other three curled, held 4 frames
Dwell click (off by default) Hold the pointer still Cursor inside a 40 px radius for 1 s
Scroll and swipe share one pose. A fist that moves vertically scrolls; a fist that flicks sideways swipes. One rule decides which, so a single hand movement can never be both. Motion that is genuinely diagonal fires nothing at all — a page that scrolls when you meant to change desktop is worse than one that waits for you to try again.
Zoom overlaps the L-Shape pose. A wide L-shape is what arms zoom, and L-Shape is also one of the four trained poses, bound to Spotlight. When the classifier is confident it is L-Shape, Spotlight wins; zoom gets the frame only when it is not. If you want the two cleanly separate, rebind one of them in the command builder.
Why the hold-and-release for clicks. A click fires when you open a held pinch, not when you close it. That means a hand that briefly passes through a pinch shape while moving does not click, and holding a pinch does not auto-repeat. The gap between the close and open thresholds is hysteresis: without it, a hand hovering at the boundary would chatter clicks on and off.

Install and run

  1. Get the code

    git clone https://github.com/liz112200/GestureFlow-Media-Controller.git
cd GestureFlow-Media-Controller
python3 -m venv venv
source venv/bin/activate
pip install -e .

  2. Grant Accessibility permission

    System Settings → Privacy & Security → Accessibility, then enable the terminal or editor you will run the app from.

    Without this, PyAutoGUI cannot move the cursor or send keystrokes, and the app will appear to recognize gestures while doing nothing. macOS requires a human at the settings pane — it cannot be scripted.

  3. Allow camera access

    macOS prompts the first time the app opens the camera. Accept it. If you dismissed the prompt, re-enable under Privacy & Security → Camera.

  4. Run it

    python -m gestureflow run

    A window opens with your camera feed and a heads-up display. Press q in that window to quit.

  5. Install your own commands

    Build a config at the command builder, then: 

    mkdir -p ~/.gestureflow
mv ~/Downloads/commands.yaml ~/.gestureflow/commands.yaml
python -m gestureflow validate

    validate checks the file and prints what each gesture is bound to. The app also re-reads the file while running, so edits apply without a restart.

Two more permissions, only if you use them. An applescript action makes macOS ask once for permission to control System Events. A screenshot shortcut needs Screen Recording. The default config needs neither.

Measuring it yourself

This site quotes no performance numbers, because they depend on your camera, CPU, and lighting. Here is how to generate them for your machine.

Latency and frame rate

python -m gestureflow bench --seconds 30

Runs the full pipeline headless for 30 seconds without touching your cursor, then prints per-stage timings and writes a JSON report. Latency comes out as p50/p95/p99 rather than a mean, because the mean hides exactly the stalls you notice. Stages are reported separately, so you can see whether MediaPipe, the classifier, or rendering is the bottleneck.

False-trigger rate

# Record yourself working normally, not trying to control anything
python -m gestureflow record takes/no-intent-1.jsonl --label no-intent --seconds 300

# Replay it and count what fired
python -m gestureflow false-triggers takes/*.jsonl

Every action over footage you labelled no-intent is a false trigger by definition. Because replays are deterministic, you can change a threshold, replay the same take, and compare honestly — which is the only way to know a tuning change actually helped.

Model accuracy

python scripts/train_model.py

Writes models/metrics.json with accuracy, per-class precision and recall, and a confusion matrix. Read the caveat it records alongside them: training rows are logged one per video frame while a pose is held, so consecutive rows are near-duplicates, and a random train/test split puts frame k in training and frame k+1 in test. The reported accuracy is an optimistic upper bound, not a generalization estimate. A split grouped by recording session would be needed for that.

Calibration

Fits the pinch thresholds to your hand. Optional — everything works without it. 

python -m gestureflow calibrate

Thresholds are already fractions of your hand's size, which handles sitting closer to or further from the camera. What it cannot handle is that hands differ from each other: one person's fully closed pinch measures a fifth of their hand scale, another's a third. If clicking feels unreliable, this is the first thing to try.

Four short recordings — pinch closed, hand open, middle-finger pinch, hand open again — and it writes ~/.gestureflow/calibration.json. Delete that file to go back to the shipped defaults. Check what is in effect with python -m gestureflow calibration.

App-context profiles

Change what a gesture means depending on which app is in front. 

version: 2
neutral_label: 0

gestures:
  - gesture: swipe_right
    name: Next desktop
    action: { type: hotkey, keys: [ctrl, right] }

profiles:
  - name: presentation
    match:
      apps: [Keynote, Microsoft PowerPoint]
    gestures:
      - gesture: swipe_right
        name: Next slide
        action: { type: keypress, key: right }

A profile lists only what it changes; everything else keeps working as it does by default. The first profile whose app list matches wins, so precedence reads top to bottom. Matching is case-insensitive on the application's name.

Reading the frontmost app needs macOS Automation permission. If it is declined, or you are not on macOS, the default profile applies and everything else carries on — the app says so once and does not nag.

Adding your own gestures

The shipped model knows four poses. Teaching it more takes about ten minutes.

  1. Collect samples

    python scripts/data_logger.py

    Hold a number key while holding a pose to record frames for that label. Aim for a few hundred per class, and vary your distance from the camera, your hand angle, and the lighting — samples all collected in one position produce a model that only works in that position.

  2. Retrain

    python scripts/train_model.py

  3. Bind the new label

    Add it in the command builder and export. The app refuses to start if a pose it can recognize has no action bound, so an unbound gesture is a startup error rather than a gesture that mysteriously does nothing.

  4. Refresh the browser demo (optional)

    python scripts/export_model_json.py

    Exports your retrained forest for the web demo and verifies it reproduces scikit-learn's predictions exactly before writing.

Optional: the local bridge

Serves this same interface from your own machine, with live gesture state. 

python -m gestureflow bridge

Opens http://127.0.0.1:8765. Because the page is then served from loopback, the WebSocket carrying live state is same-origin and works in every browser — which it would not reliably do from an https:// page, since browsers disagree about connecting to ws://localhost and Safari is the strictest. With the bridge running, the command builder can write your config directly instead of going through the Downloads folder.

It binds to loopback only, checks the Origin header on upgrade, and re-validates any pushed config exactly as it would one read from disk.

Troubleshooting

SymptomLikely cause
Gestures are recognized in the HUD but nothing happens Accessibility permission is missing for the terminal you launched from
App exits with a message about an unbound gesture Your config has no action for a pose the model can predict. Bind it, or retrain without that class.
"Camera lost — reconnecting" in the window Another app took the camera. The browser demo on this site counts.
Cursor moves when you meant to scroll Your fist is not fully closed. All four fingertips must sit below their knuckles.
Clicks fire when you did not mean them Raise CLICK_HOLD_FRAMES, or measure it: record a no-intent take and replay it.
Poses are recognized unreliably The shipped model was trained on one person in one room. Collect your own samples and retrain.
Clicking is unreliable, but poses are fine Run gestureflow calibrate. The default pinch thresholds may not suit your hand.
Nothing responds and the window says PAUSED The kill switch is on. Hold index and pinky up, middle and ring down, for a second and a half.
A long pinch starts dragging when you wanted a click Release sooner, or set DRAG_HOLD_SECONDS higher.
Swiping also scrolls the page Flick more horizontally. Motion that is close to diagonal deliberately fires neither.
